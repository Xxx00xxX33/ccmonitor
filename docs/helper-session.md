# 转发会话（转发模式 B）

ccmonitor 有两种转发模式（DESIGN.md 第 5 节），用来处理界面写入发不出去的 prompt：

- **模式 A（默认）：不借助 agent。** 守护进程自己排队：会话正在运行时等这一轮结束再发，界面写入故障时自己重试。不需要转发会话。
- **模式 B：借助转发会话。** 交给一个常驻的转发会话，用 Desktop 自带的「会话间发消息」转过去。转发会话用最便宜的模型（如 Haiku）、effort low、Bypass permissions，每 6 小时换一次班。还没有转发会话、或者它正在换班时，消息先按模式 A 排队。

## 切换模式

几个入口，切的是同一份转发模式，选择会写进 `%USERPROFILE%\.ccmonitor\relay-mode.json`，重启后保持：

- ccmonitor 窗口的状态页：转发模式选 A 或 B。选 B 而还没有转发会话时，会显示新建步骤和「复制启动指令」按钮（见下面「怎么建」）。
- Telegram：`/mode` 查看，`/mode a`、`/mode b` 切换。从 Telegram 切到 B 时没法新建转发会话，ccmonitor 会提示你到电脑上按窗口里的说明建。
- 运行 `python -m ccmonitor.relaymode a`、`b` 或 `status`（自己运行或让任一 Claude 会话运行都行）。切到 B 而还没有转发会话时，这条命令打印新建步骤和启动指令。

切回 A 后转发会话就不再被使用，可以归档。

## 每 6 小时换班

会话自己清空上下文会连带停掉转发源，清空后也没人唤醒它（2026-10-12 实测），所以换班由守护进程用界面写入来做：

1. 转发会话连上后满 6 小时，并且你处于离开状态时开始。在电脑前时推迟到你离开。
2. 换班和转发在同一个工作线程里排队，所以正在进行的转发一定先完成；换班期间新来的消息按模式 A 排队。
3. 在转发会话输入框里写入 `/clear`，再写入启动指令。实测 `/clear` 后模型、effort 和权限模式都保留。
4. 转发会话重新连上转发源就算换班完成，重新计时。3 分钟内没连上，在 Telegram 提醒，消息继续按模式 A 排队。
5. `/clear` 写入失败时 30 分钟后再试；转发会话正忙时下一分钟再试。

换班不新建也不删除会话，旧的对话可以在 Desktop 里用「Resume previous session」找回。删除会话每次都要你在电脑上确认，所以 ccmonitor 不做。

写入的备选路径（DESIGN.md 第 5 节）。界面写入不可用时，ccmonitor 把 prompt 交给一个常驻的 Desktop 会话，由它用 Desktop 自带的「会话间发消息」转给目标会话。它不碰 Desktop 界面，也不切换你屏幕上的会话。

## 什么时候走这条路

只用于发 prompt（自由消息和点选项），只在离开状态下，并且只在界面写入出现以下情况时：

- 目标会话正在运行：消息会排队，这一轮结束后执行。
- 界面写入坏了：找不到窗口、切换会话失败、填字失败、脚本出错等。

以下情况不走这条路：

- 界面写入已经发出。
- 点了发送但没确认到：这条可能已经发出，再转发会发两次。
- 审批：辅助会话做不了审批，「允许一次 / 拒绝」只能走界面写入或 Claude app。

## 已知限制（2026-10-11 实测）

- 目标会话会看到这条消息来自另一个会话，并把它当作「同事的请求」照做，权限按目标会话自己的设置。
- 它不会因为这种消息改权限设置、CLAUDE.md 或配置，也不会把它当作对待审批请求的批准。这类事要在电脑上或用 Claude app 做。
- 辅助会话和目标会话的权限模式要一致（都用 bypass），否则跨会话消息会先等目标会话的用户确认。
- 转发的文字会出现在辅助会话自己的记录里。这和目标会话本来就会记录这条 prompt 一样，都由 Claude Code 保存；ccmonitor 自己不落盘。
- 辅助会话每转发一次要用一轮模型调用；上下文会慢慢变长，由 Claude Code 自动压缩。

## 怎么建

转发会话由你手动新建，不让别的会话代建：会话新建会话要用的工具不是每个 Claude Desktop 版本都有（2026-10-14 实测缺 `start_session`），ccmonitor 要在任何人的电脑上都能用。

1. 确认 ccmonitor 在运行（它在 47822 端口等转发会话连上来），并已切到模式 B。
2. 在 Claude Desktop 里新建一个会话：文件夹选 ccmonitor 的仓库目录（不用 worktree），模型选最便宜的（如 Haiku），effort 选 low，权限模式选 **Bypass permissions**。权限不是 Bypass 的话，每次转发都要你在电脑上确认。
3. 在 ccmonitor 窗口的状态页点「复制启动指令」，作为这个会话的第一条消息发出去。也可以运行 `python -m ccmonitor.relaymode b`，从打印的内容里复制。
4. 在 Telegram 发 `/status`，看到「转发会话：已连接」就好了。

启动指令以 `ccmonitor/relaymode.py` 里的 `SETUP_PROMPT` 为准，换班时也发这一段。它不是固定文本：里面的 Python 和脚本路径是按这台电脑上运行 ccmonitor 的那个 Python 和仓库位置生成的，所以要从窗口或命令复制，不要从别处抄。它要求转发会话先确认自己有 `Monitor` 和 `mcp__ccd_session_mgmt__send_message` 两个工具，缺一个就回一句「本环境缺少……请切回转发模式 A」并停下；改标题用的 `set_session_title` 没有也不要紧，换班按转发会话当时的标题找它。

## 停用

切回模式 A（`/mode a`），再归档这个会话。只归档不切模式时，ccmonitor 显示「转发会话：未连接」，消息照样按模式 A 排队。
